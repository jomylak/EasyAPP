- Google Careers (careers.google.com) requires signing in with a Google account before applying -- no guest/email application path exists. The test browser's default Google Workspace session was blocked ("Service Not Allowed"), and switching to a personal Gmail account tripped Google's automated-browser detection ("This browser or app may not be secure"). RESULT:FAILED:sso_required is correct here; this isn't solvable by prompting alone without a pre-authenticated, bot-detection-safe Google session.
- Tesla's own site (tesla.com/careers) returned a 403 from its CDN (Akamai) on every page including the job URL when accessed via automated browser -- likely bot-detection at the edge, not something the agent did wrong. Tesla's actual ATS (Workday, tesla.wd1.myworkdayjobs.com) was also down for scheduled maintenance during this test, so this result may be time-of-day-specific rather than a permanent block. Worth a retry at a different time before concluding Tesla is unreachable.
- Amazon.jobs (amazon.jobs, Amazon's in-house ATS) is NOT a genuine failure case at 900s -- the agent correctly parsed a long multi-page application (select2 widgets, work-eligibility radio grid, review page) and reached the final Review & Submit step before hitting the timeout. This platform looks reliable given a realistic time budget (15-25 min), same pattern as Oracle HCM/Taleo.

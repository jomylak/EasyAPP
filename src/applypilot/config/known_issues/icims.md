- hCaptcha challenges on this platform can return a CapSolver errorId (API solve genuinely failed for the sitekey) -- fall back to the accessibility/text-challenge option (open the hCaptcha checkbox menu, look for an audio/accessibility alternative), which has solved it manually when the API could not.
- The hCaptcha accessibility/text-challenge fallback (see the other entry in this file) is NOT reliable: on one run it correctly solved the puzzle and the Acknowledge button stayed enabled; on another, the same fallback answered the puzzle correctly but the underlying hCaptcha response token never registered, leaving the button disabled and forcing a full page reload -- which re-triggers a fresh hCaptcha and can loop indefinitely. Treat a still-disabled button after an apparently-solved accessibility challenge as a dead end for this run rather than retrying the same fallback again.
